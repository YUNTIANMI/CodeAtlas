# AI 软件工程研发助手
## 需求规格说明书（SRS）

**项目名称：** AI 软件工程研发助手  
**项目定位：** 面向个人开发者与小型开发团队的 AI 辅助研发平台  
**文档版本：** V1.0  
**文档状态：** 初版

---

## 1. 项目概述

### 1.1 项目背景

随着 AI 大模型的发展，代码生成、代码解释、Bug 分析等能力已经能够显著辅助软件开发。

但单纯调用大模型 API 的 AI 聊天工具存在明显局限：

1. AI 不理解当前项目完整上下文。
2. AI 无法准确了解项目自身的代码、文档和 Git 历史。
3. 普通聊天模式难以形成持续积累的项目知识。
4. AI 给出的回答缺少可靠的项目来源。
5. AI 代码分析、Bug 分析和知识检索通常彼此割裂。

因此，本项目希望构建一个以真实软件项目为核心上下文的 AI 研发辅助平台。

系统将项目源码、技术文档、需求文档、Git 信息等内容进行统一管理，并通过知识检索、RAG、AI 分析和工具调用，为开发者提供项目问答、代码分析、Bug 分析和研发辅助能力。

---

## 2. 项目目标

本项目不是一个简单的 AI Chat Demo。

核心目标是：

> 建立一个能够理解软件项目上下文，并参与软件研发过程的 AI 辅助开发平台。

系统最终应能够：

- 管理多个软件项目。
- 保存项目文档和源代码。
- 导入 GitHub/Git 仓库。
- 建立项目知识库。
- 根据项目上下文进行 AI 问答。
- 对代码进行 AI Code Review。
- 根据错误日志进行 Bug 分析。
- 分析 Git Commit。
- 为 AI 提供代码搜索、文档搜索、Git 查询等工具。
- 保留 AI 分析过程和历史记录。

# 3. 用户角色

## 3.1 普通用户

可以：

- 注册账号。
- 创建项目。
- 编辑项目资料。
- 上传文档。
- 导入 Git 仓库。
- 查询项目知识。
- 使用 AI 助手。
- 查看代码分析结果。
- 查看 Bug 分析结果。

## 3.2 项目成员

项目创建者可以邀请其他用户加入项目。

项目成员可以根据权限：

- 查看项目。
- 查看文档。
- 查看代码。
- 使用 AI 助手。
- 创建分析任务。

## 3.3 项目管理员

管理员可以：

- 管理项目成员。
- 修改项目配置。
- 删除项目内容。
- 配置 Git 仓库。
- 查看 AI 使用记录。

- 项目名称

- 项目类型
- 技术栈

- 创建时间
- 更新时间

```text
项目：个人项目管理平台

技术栈：
Java
Spring Boot
React
TypeScript
MySQL
Redis
```

- TXT
- PDF

- 需求文档

# 8. Git 仓库管理

用户可以配置 Git 仓库。

系统可以获取：

- Repository 信息
- Commit
- Branch
- Commit Message

- 修改时间
- 作者

# 9. 项目知识库

这是系统核心功能之一。

系统需要将：

```text
项目文档
+
源代码
+
Git 信息
+
项目说明
```

转换成可以被 AI 检索的知识。

处理过程：

```text
原始数据
 ↓
内容解析
 ↓
文本切分
 ↓
Chunk
 ↓
Embedding
 ↓
向量数据库
```

---

# 10. AI 项目问答

用户可以提出：

> “这个项目的登录流程是什么？”

系统应：

```text
用户问题
 ↓
检索相关知识
 ↓
获取代码/文档上下文
 ↓
提交给大模型
 ↓
生成回答
 ↓
返回引用来源
```

回答应该尽可能带有：

- 文件名称
- 文件路径
- 文档名称
- Git Commit
- 相关代码位置

避免 AI 在没有项目依据的情况下自由生成答案。

---

# 11. AI Code Review

用户可以提交：

- 单个代码文件
- 代码片段
- Git Commit
- Git Diff

系统进行 AI Code Review。

分析内容包括：

### 正确性

- 潜在 Bug
- 异常处理问题
- 边界问题

### 性能

- 不必要的循环
- 潜在的高复杂度操作
- 数据库查询问题

### 安全

- SQL 注入风险
- 敏感信息泄露
- 权限控制问题

### 可维护性

- 代码重复
- 模块耦合
- 命名问题
- 结构问题

最终输出：

```text
问题等级
问题位置
问题说明
风险
修改建议
```

---

# 12. Bug 分析

用户可以提交：

- 错误信息
- Stack Trace
- 日志
- 相关代码

系统执行：

```text
错误日志解析
 ↓
定位错误
 ↓
搜索项目代码
 ↓
检索相关文档
 ↓
AI 分析
 ↓
生成可能原因
 ↓
生成修复建议
```

结果包括：

- 错误摘要
- 可能原因
- 相关文件
- 调用链
- 修复建议
- 建议测试方案

---

# 13. AI Agent

后期系统支持 AI 调用内部工具。

工具包括：

```text
searchCode()
readFile()
searchDocument()
searchGitCommit()
getProjectStructure()
getDatabaseSchema()
```

AI 根据用户任务决定调用哪些工具。

例如：

> “帮我分析这个登录 Bug。”

Agent：

```text
读取错误日志
 ↓
搜索登录相关代码
 ↓
查看相关 Commit
 ↓
分析调用链
 ↓
生成报告
```

# 15. 权限要求

不同角色拥有不同权限。

例如：

```text
OWNER
ADMIN
MEMBER
VIEWER
```

系统需要确保：

> 用户只能访问自己拥有权限的项目内容。

尤其是：

- 源代码
- 项目文档
- Git 信息
- AI 对话

不能因为修改 URL 或请求参数而访问其他用户数据。

# 17. MVP 范围

第一版只实现：

```text
用户系统
    ↓
项目管理
    ↓
文档上传
    ↓
代码上传
    ↓
知识库
    ↓
RAG 问答
    ↓
AI Code Review
```

暂时不实现：

- 多 Agent
- 消息队列
- Kubernetes
- 自动修改代码
- 自动 Git Push
- 微服务

# 18. 成功标准

当以下流程完整运行时，V1 可以认为完成：

```text
用户注册
 ↓
创建项目
 ↓
上传 README
 ↓
上传源代码
 ↓
建立知识库
 ↓
向 AI 提问
 ↓
系统检索项目内容
 ↓
AI 根据项目内容回答
 ↓
回答附带来源
```

并能够完成：

```text
提交代码
 ↓
AI Code Review
 ↓
得到结构化分析报告
```
