# ADR-005：Agent 只读，且只能通过受控工具访问项目

- **状态：** 已接受
- **日期：** 2026-09-12

## 背景

系统规划了 AI Agent 能力：用户提出任务（如"帮我分析这个登录 Bug"），AI 自主决定调用哪些工具获取项目资料，最终生成分析报告。

需要明确 Agent 的权限边界。

## 决策

1. **Agent 只读**：不允许修改代码、不允许 Git Push、不允许修改数据库。
2. **工具化访问**：Agent 只能通过预定义工具获取项目资料。

```text
Tool
├── SearchCodeTool          搜索代码
├── ReadFileTool            读取文件
├── SearchDocumentTool      搜索文档
├── SearchGitCommitTool     查询 Git 提交
└── GetProjectStructureTool 获取项目结构
```

3. **全量记录**：每次工具调用记录工具名、输入、输出、耗时、成功与否。

## 理由

1. **可控性**：AI 的输出具有不确定性，写操作一旦出错会造成不可逆的代码或数据损坏。
2. **可审计**：工具调用被完整记录，出现问题时能回放 AI 的决策过程。
3. **安全性**：Agent 不接触数据库底层，避免 Prompt 注入导致越权访问。
4. **权限统一**：工具内部复用与人工操作相同的权限校验逻辑，天然实现"用户只能查自己有权限的项目"。
5. **可调试**：工具边界清晰，便于定位是检索问题还是模型问题。

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| 允许 Agent 直接写文件并提交 | 风险过高，AI 误判会直接污染代码库 |
| 允许 Agent 直连数据库查询 | 破坏分层，且存在注入与越权风险 |
| 完全由人工指定上下文（无 Agent） | 灵活性不足，复杂任务需要多轮检索 |

## 影响

- Agent 的价值限于"分析与建议"，最终修改动作由开发者完成
- 每个工具必须内置 `projectId` 范围限制，防止跨项目检索
- `ai_execution_logs` 表会记录完整工具调用链，用于调试与成本统计

## 复审条件

当系统具备以下能力后，可重新评估是否开放受控的写操作：

- 完整的自动化测试覆盖（可验证 AI 修改是否正确）
- 代码变更的自动回滚机制
- 人工确认环节（AI 生成 Patch → 人工审核 → 应用）
