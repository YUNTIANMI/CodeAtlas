# ADR-001：选择 MySQL 作为主数据库

- **状态：** 已接受
- **日期：** 2026-09-12

## 背景

系统需要存储用户、项目、成员、文档、代码文件、Git 提交、AI 会话与分析结果等业务数据。这些数据具备明确的关联关系（项目→成员、项目→文档、会话→消息），且对一致性要求较高。

## 决策

采用 **MySQL 8.0** 作为唯一主数据库（关系型数据），向量数据另由 Qdrant 承担。

## 理由

1. **数据模型高度关系化**：项目、成员、文档、会话之间存在大量一对多与多对多关系，关系模型天然适配。
2. **与 Spring Boot 生态无缝**：JPA / MyBatis 支持成熟，个人开发成本低。
3. **事务支持可靠**：知识库构建、成员变更等操作需要事务保证。
4. **个人可维护**：单机部署简单，无需额外的运维投入。
5. **SQL 成熟**：复杂查询（统计、审计、检索日志）用 SQL 表达最直接。

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| PostgreSQL | 功能更强（如 JSONB、全文检索），但个人项目收益有限，且团队生态不如 MySQL 普遍 |
| MongoDB | 文档型适合非结构化数据，但本项目核心数据是强关联的，且需要事务 |
| SQLite | 部署最简，但并发能力与后续扩展不足 |

## 影响

- 需额外引入 Qdrant 承担向量检索，形成"MySQL + Qdrant"双库结构
- 大字段（代码正文、日志）使用 `LONGTEXT`，不参与索引
- 采用逻辑外键，不使用物理外键约束，便于后续拆分与迁移
