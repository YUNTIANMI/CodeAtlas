# ADR-003：采用 JWT 无状态认证

- **状态：** 已接受
- **日期：** 2026-09-12

## 背景

系统需要支持注册、登录、退出与权限控制。后端为单体 Spring Boot 应用，前后端分离部署。

## 决策

采用 **JWT（JSON Web Token）+ Spring Security** 实现无状态认证：

- 密码使用 **BCrypt** 加盐哈希存储，禁止明文或可逆加密
- 登录成功后签发 JWT，前端在 `Authorization: Bearer <token>` 中携带
- Token 有效期 2 小时
- Redis 仅用于辅助：Token 黑名单（退出登录）、登录失败限流

## 理由

1. **前后端分离友好**：无状态 Token 不依赖服务端 Session，便于后续横向扩展。
2. **实现成本低**：Spring Security + JWT 是成熟方案，无需额外的 Session 存储。
3. **与限流天然结合**：配合 Redis 可快速实现登录失败次数限制。
4. **便于权限扩展**：可将项目角色写入 Token 之外的查询逻辑，避免 Token 膨胀。

## 备选方案

| 方案 | 未采用原因 |
|---|---|
| Session + Cookie | 服务端需维护会话状态，前后端分离下需处理跨域与 CSRF，复杂度更高 |
| OAuth2 第三方登录 | 增加外部依赖，MVP 阶段非必需 |
| Session + Redis 集中式 | 可控性强（可即时踢下线），但引入强依赖，单体阶段收益有限 |

## 影响

- 退出登录需配合 Redis 黑名单，因为 JWT 本身无法主动失效
- Token 中仅存放 `userId` 与基础信息，**不存放项目角色**（项目权限在 Service 层实时校验，避免权限变更延迟生效）
- 必须强制 HTTPS，防止 Token 在传输中被截获
